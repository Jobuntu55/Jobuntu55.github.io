Lab 02 - Mise en place d'un serveur de fichiers Samba

Objectif

Mettre en place un serveur de partage de fichiers sous Linux permettant à des clients Windows d'accéder à des ressources partagées via le protocole SMB.

Environnement

  • Système d'exploitation : Debian 12 (Bookworm)
  • Machine virtuelle : VirtualBox
  • Adresse IP du serveur : 192.168.1.113
  • Service utilisé : Samba

Compétences travaillées

  • Installation de services Linux
  • Gestion des permissions
  • Configuration réseau
  • Édition de fichiers de configuration
  • Gestion des utilisateurs Samba
  • Diagnostic et dépannage

Installation de Samba

Mise à jour des paquets :

apt update

Installation du serveur Samba :

apt install samba -y

Vérification du service :

systemctl status smbd

Résultat attendu :

active (running)

Création du dossier partagé

Création du répertoire :

mkdir /srv/partage

Attribution des permissions :

chmod 777 /srv/partage

Vérification :

ls -ld /srv/partage

Résultat :

drwxrwxrwx

Sauvegarde de la configuration

Avant modification :

cp /etc/samba/smb.conf /etc/samba/smb.conf.bak

Configuration du partage

Modification du fichier :

nano /etc/samba/smb.conf

Ajout à la fin du fichier :

[Partage]
path = /srv/partage
browseable = yes
writable = yes
guest ok = no
read only = no
valid users = jonathan
force user = root

Explication des paramètres

[Partage]

Nom du partage visible sur le réseau.

Accès :

\\192.168.1.113\Partage

path

path = /srv/partage

Dossier réel partagé sur Linux.

browseable

browseable = yes

Rend le partage visible sur le réseau.

writable

writable = yes

Autorise la modification des fichiers.

guest ok

guest ok = no

Interdit l'accès anonyme.
Une authentification est obligatoire.

read only

read only = no

Autorise l'écriture.

valid users

valid users = jonathan

Seul l'utilisateur jonathan est autorisé à accéder au partage.

force user

force user = root

Toutes les opérations sur le partage sont exécutées avec les droits de root.
Cette configuration est utilisée uniquement pour simplifier le laboratoire.

Vérification de la configuration

Validation du fichier :

testparm

Résultat :

Loaded services file OK

Redémarrage du service

Après modification :

systemctl restart smbd

Vérification du port réseau

Contrôle de l'écoute réseau :

ss -tuln | grep 445

Le port :

445/TCP

doit être en état :

LISTEN

Ce port est utilisé par le protocole SMB.

Création d'un utilisateur Samba

Vérification de l'utilisateur Linux :

id jonathan

Création du mot de passe Samba :

smbpasswd -a jonathan

Vérification :

pdbedit -L

Résultat :

jonathan:1000:Jonathan

Diagnostic local avec smbclient

Installation :

apt install smbclient -y

Test du serveur :

smbclient -L localhost -U jonathan

Résultat :

Sharename
---------
Partage
IPC$
jonathan

Ce test confirme :

  • Samba fonctionne
  • L'authentification fonctionne
  • Le partage est correctement publié

Tests côté Windows

Accès au partage :

\\192.168.1.113\Partage

Conflit d'identifiants Windows

Message :

Le dossier réseau spécifié est actuellement mappé avec un nom d'utilisateur et un mot de passe différents

Solution

Suppression des anciennes sessions :

net use * /delete /y

Difficultés rencontrées

Authentification Samba

Après activation de :

guest ok = no

Windows refusait la connexion.

Diagnostic

testparm
pdbedit -L
smbclient -L localhost -U jonathan

Conclusion

Le serveur Samba fonctionnait correctement.
Le problème provenait des identifiants mémorisés côté Windows.

Arborescence Linux découverte

Pendant ce laboratoire, découverte de l'organisation classique d'un service Linux : 

Programme     → /usr
Configuration → /etc
Logs          → /var/log
Données       → /srv

Application à Samba :

Programme     → /usr/sbin/smbd
Configuration → /etc/samba/smb.conf
Logs          → /var/log/samba
Données       → /srv/partage

Conclusion

Ce laboratoire a permis de mettre en place un serveur de fichiers Samba sous Debian et de comprendre :

  • Le fonctionnement d'un service Linux ;
  • La structure des fichiers système ;
  • Les permissions Linux ;
  • L'authentification Samba ;
  • Le dépannage réseau ;
  • La communication entre Linux et Windows.

Ce laboratoire constitue une première approche concrète de l'administration d'un serveur de fichiers en environnement professionnel. ✅
